## Use policy for this project

Choose the smallest direct tool set that achieves the approved task. Prefer the existing GitHub workflow and local tools; use visual tooling when it answers a design question. Delegate independent bounded reviews rather than copying the entire project into many agents. Recheck connection/permission and applicable skill requirements when a capability becomes relevant. Never add a backend, hosted model, deployment or paid generation dependency because a tool exists.

A failed approval review is not permission to route the same action around the check. Track pending remote work and continue unrelated local/read-only tasks where possible. Do not describe local-only changes as pushed or merged.
